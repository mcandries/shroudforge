# Game overlay module

This module draws mod-defined zones (text, images, frames) over the game image. It is an implicit Vulkan layer, `shroudforge_overlay.dll`, shipped in `shroudforge/overlay` with its manifest `shroudforge_overlay.json`.

The bootstrap (`modules/entrypoints/windows-bootstrap/startup.cpp`) enables it in the game client only. It adds the folder to `VK_ADD_IMPLICIT_LAYER_PATH` and sets `SHROUDFORGE_OVERLAY_ENABLE=1` before Enshrouded creates its Vulkan instance. It skips this when `modules.gameOverlay.enabled` is false in `modloader-config.json`, or when `SHROUDFORGE_OVERLAY=0`. Processes started by the game inherit these variables, but the layer does nothing outside `enshrouded.exe`.

| Action | Implementation |
| --- | --- |
| Insert the layer, track devices, queues and swapchains | `src/layer_entry.cpp` |
| Draw the zones in the presented image with Dear ImGui | `src/renderer.cpp` |
| Lay out and draw zones and items | `src/draw_scene.cpp` |
| Store zones and options, C API for the runtime | `src/scene.cpp` |
| Decode PNG and JPEG images | `src/load_image.cpp` |
| Read the player options, handle the show/hide key | `src/player_options.cpp` |
| Player options in the Modloader (F9) | `ui/settings.ts`, `modules/loader-config/ui/show-module-settings.tsx` |
| Log to `shroudforge_overlay.log` beside the DLL | `src/log.cpp` |
| Present test with a readback | `tests/present_test.cpp` |

## Rendering

Mods describe zones (retained mode). At each `vkQueuePresentKHR` with at least one visible zone, the layer:

1. records a render pass over the presented image (load, draw, store);
2. submits it after the game's wait semaphores;
3. makes the real present wait on its own semaphore.

Without a visible zone, the present is passed through untouched and the layer does no GPU work. The ImGui backend starts on the first present that has something to draw, on that queue. Unsupported cases are not drawn: a swapchain without `COLOR_ATTACHMENT` usage, or a format other than 8-bit or 10-bit UNORM/SRGB (HDR formats are left alone).

Fonts are TrueType or OpenType files rasterized on demand by Dear ImGui 1.92. The default font is Segoe UI, or the ImGui default if it is missing. Images and fonts stay loaded for the session (at most 100 images).

## Player options

The player edits them in the Modloader (F9, Settings, Modules, Game overlay). They are saved in `modules.gameOverlay` of `modloader-config.json`:

| Key | Default | Effect |
| --- | --- | --- |
| `enabled` | `true` | Read by the bootstrap at game start: the layer is not loaded at all when false. Also read live by the layer, which stops drawing. |
| `scale` | `100` | Size of every zone, in percent (25 to 400), on top of the screen scale. |
| `opacity` | `100` | Opacity of every zone, in percent. |
| `hideKey` | `""` | Keyboard shortcut that shows or hides every zone while the game has focus, as a ShroudForge SDL binding such as `Shift+SDL:69` (Shift+F12); empty for none. Captured in F9 with the shared keybind field (`hotkeys/ui/edit-keybind.tsx`). The layer reads its keyboard part; a mouse alternative is ignored. |
| `hideInMenus` | `true` | No zone while a game menu is open. A menu is open when the game window has the focus and shows the mouse cursor: Enshrouded hides it while playing, its shape menu included, and shows it in the inventory, the map and the pause menu. The cursor must stay shown for 250 ms: while playing, the game shows it for a frame or two now and then, which would make the zones blink. Mods read it as `status().menu`. |

The layer rereads the file at most once per second, only when its modification time changed, so changes apply while the game runs.

## C API

The runtime (same process) finds the layer with `GetModuleHandleW(L"shroudforge_overlay.dll")` and calls these exports. All strings are UTF-8.

| Export | Use |
| --- | --- |
| `int ShroudforgeOverlay_ApiVersion()` | Version of this API (1). |
| `int ShroudforgeOverlay_SetZone(owner, id, json, error, error_size)` | Create or replace zone `id` of mod `owner`. Returns 0, or -1 with a message. |
| `void ShroudforgeOverlay_RemoveZone(owner, id)` | Remove one zone. |
| `void ShroudforgeOverlay_ClearOwner(owner)` | Remove every zone of a mod. |
| `int ShroudforgeOverlay_GetStatus(out, out_size)` | `{"active", "width", "height", "scale"}` of the current output. |

Paths in zones must be absolute. Mods use the Lua API `shroudforge.overlay` (`set`, `remove`, `clear`, `status`, documented in `modules/mod-runtime/lua/shroudforge/v1/definitions/mod_api.lua`). The runtime resolves the `image` and `font` fields inside the mod's folder (`resolve_overlay_paths.rs`; zip packages are refused) and calls the layer (`game_overlay.rs`). A mod's zones are removed when it stops running (`session/record_runtime_state.rs`). Limits: 32 zones per mod, 256 items per zone, 4096 bytes per text, rows nested 3 deep. `status().features` lists what the layer knows beyond its first version, for a mod to fall back without it (a layer ignores the fields it does not know): `dashes` (`dashes` on lines, `boxes` in `world` items), `same_mesh` (faces and solids kept when a zone gives the same cells again), `hide_hidden` (`hide_hidden`, `hidden_dashed` and `hide_own` in the `cells` of `world` items), `only_in_solids` (in those `cells`), `game_depth` (the world items drawn against the game's depth, game-depth.on), `blobs`: a `cells` or `data` text may be `{"blob": id}`, a text given before with `ShroudforgeOverlay_SetBlob(owner, id, data, size)` (dropped with `ShroudforgeOverlay_DropBlob` or with the mod's zones). The runtime gives every string of 16 KiB or more of a zone that way, once while the mod gives the same Lua string (`pass_overlay_blobs.rs`): a 3D view is not copied into JSON again when only its zone's labels or lines change.

Diagnostic, the game's render passes (`render_probe.cpp`): with a file `render-probe.on` next to the layer when the game starts, the layer also follows how the game records and submits its frames (images and their views, render passes and framebuffers, `vkCmdBeginRenderPass*` and `vkCmdBeginRendering*`, draws, dispatches, image copies, submits) and logs, for frame 600 then every 1800th (6 in all), each pass in submission order: queue, size, draws, the dispatches and copies before it, its color and depth attachments (format, image and its size, load and store). Depth images are logged when created (format, size, usage). Without the file nothing of this is intercepted.

Test, the game's scene depth (`game_depth.cpp`, `renderer.cpp`): with a file `game-depth.on` next to the layer when the game starts, the layer copies the game's scene depth as the game draws it: after each dynamic rendering pass whose depth attachment (D32, one level, created with `TRANSFER_SRC`) is stored and shaped like the screen (at least 30 % of its area), it records into the game's command buffer barriers and a copy into an image of its own, the game's image put back in its layout, ours left in `SHADER_READ_ONLY_OPTIMAL` (as ReShade's generic depth; read at the present, Enshrouded's depth held only zeros, its memory used again later in the frame). The overlay uses the last copy submitted since the last present or the one before, and the camera read as that copy was recorded (`KfcRuntimeReadLocalCamera`): the world items are drawn with the camera of the scene in the depth, not the one read at the present (`camera=present` in `game-depth.on` for the latter). While a world item has `depth_picture = true` (a diagnostic), it blits the copy, reduced to 640 across, into a cached host buffer every 6th frame, and shows it top right, the distance on a log scale from 0.5 m (bright) to 2 km (dark), with a line in the log every 5 s. The render probe is off meanwhile (both take the same functions).

With the scene depth found, the faces and edges of `cells` with `hide_hidden` are drawn against it instead of tested on the CPU: sent with their depth as the game's (`near / distance`, interpolated along the screen as the game's) to our own pipeline (`shaders/world_depth.vert`, `.frag`, compiled into `src/world_depth_spirv.h` by `shaders/compile.py` with the Vulkan SDK's `glslc`; the header is committed), drawn in the zones' pass before the zones, the game's depth sampled in a read-only layout and put back in its own after. A fragment more than `margin` meters behind the game's surface is left out, or shown as a dash on an edge with `hidden_dashed`; trees, objects and characters hide the cells too. `game-depth.on` may hold `near=0.01 margin=0 camera=gpu` (read again when it changes): the game's near distance (1 cm; a world item's `depth_near`, meters or `matrix`, the GPU camera matrix's, says it instead), the margin (the game's blocks jut out of their cells: cells drawn on them, to remove or replace, or next to them, show that far behind the game's surface), which camera draws the world items (a world item's `depth_camera`, `gpu`, `copy` or `present`, says it instead; its `depth_margin`, meters, the margin; its `face_offset`, meters (`face_offsets`, `{char = meters}` or `{char = {sides, top, bottom}}`, per cell character and direction), its cells drawn that much larger where their surface is open, faces pushed out and edges longer at outer corners, shorter at inner ones, unchanged where a cell touches only along the edge, as the game draws its blocks past their cells). The world items are drawn in a pass of their own before the zones', with a depth image of its own (reversed, cleared to 0): in the solid style (`hide_own`) it is tested and written, so that the nearest of the build's faces shows; edges keep 5 cm more margin than faces, so that they still show where a cell rests on the game's surface. The wire view (the smooth style, with `hide_hidden` or not): our faces' nearest depth is drawn first in a pass of its own, then in the zones' pass a face behind the game's surface or behind our nearest face is left out, an edge hidden by something 30 cm (or the largest face offset and 10 cm) or more before our nearest face is left out (dashed without `hide_hidden`), margins counted across the game's surface (longer along the view at a grazing angle, its slope read from the neighbouring texels), an edge hidden otherwise (by the build itself, or the game's block it sits in) is dashed; the cells stay on the grid, `face_offsets` only adding to the margin of their faces (and edges): `gpu` (default), the scene's camera as the game hands it to the GPU (`gpu_camera.cpp`: the descriptor sets bound up to the end of the scene's pass and the device addresses in its push constants are followed; now and then, until found, up to 4 KB of each, 64 KB in all, are searched for a camera block, a view-projection matrix with reversed infinite depth then the eye, near the input camera; then only those 76 bytes are read at each submit of the scene; the log tells every 5 s how it goes), else `copy`, the camera read as the depth's copy was recorded, or `present`, the one read at the present. In Remove mode (`hidden_dashed` with `hide_hidden`, the wire view, `solids` given), and with `cells.through_blocks` (Build's wire view, the cells to build counted as blocks), no distance is guessed: an edge hidden by the game's surface is dashed when that surface is the one of a block seen through: walking the grid of the world's blocks (the `solids`, a bit per cell in a storage buffer, then the build's own cells, which the solids leave out, in a second run of bits) cell by cell from the edge toward the eye, the game's surface lies in a filled cell, or no farther than one and a half the largest face offset and 5 cm from the box of the filled cell the walk just left (a corner's bumps count diagonally), or, lying in the air, from a cell of the build around it; air may be crossed only toward cells of the build (removed, air, removed: seen); a kept block after air (a block apart before the build) or the surface in the air (a character, a tree), the edge is left out. In the solid style no edge is dashed, `hidden_dashed` or not. With the GPU camera, its matrix's temporal anti-aliasing jitter (rows 0 and 1 holding a part of the gaze row, square to them otherwise) is taken out, the build steady on the image; a world item's `depth_jitter = "keep"` keeps it. `cells.one_shape = true` makes every drawn character one shape: no face between two of them, creases where the whole shape turns (a build whose characters only say what block was there). `cells.texture = {side, top, bottom}`, each `{data, width, height, levels, tiling}` (`data` the BC7 levels as the game stores them, largest first, given as a blob; `tiling` repeats a meter), textures the faces of the solid style: each texture made once on the GPU (BC7, an UNORM view: its values as stored, as the overlay's colors are), copied in a frame's commands and kept while an item holds its data (`cells.texture_keep`, a list of such data, holds textures not drawn: a material used again is not made again); the faces take the texture of their sides, top or bottom, laid along the world's axes from a multiple of 64 m, times the face's light (status feature `textures`). `cells.texture_light = true` lights them as the game lights what stands around (the light view): the layer copies the game's G-buffer color (a pass writing four colors or more, the first a screen-shaped R8G8B8A8_UNORM, one an A2B10G10R10; those images made copyable) and the image shown (the swapchain made copyable), each a quarter of its size, and a textured pixel takes the image shown divided by that color, summed over taps around it (the sky and too dark a color left out, surfaces far in depth weighing less). `cells.dash_opacity` (0 to 1, 220 / 255 by default) is the opacity of a hidden edge's dashes. `cells.back_edges` (0 to 1) draws, in the wire view, the creases between two faces turned away from the eye too, and is the opacity of the dashes behind the build's own faces by more than their margin (inside the build or at its back; those hidden by the world alone stay at `dash_opacity`) (a crease no longer vanishes as the view turns). `face_offsets_largest = true` draws every face with the largest offsets of the characters the cells hold, direction by direction. The aimed face logs, every 5 s, the near distance the depth read back gives there.

## Zone format

Sizes and offsets are reference pixels of a screen 1080 pixels high, or `reference` pixels high when the zone sets it (900 for a design made at 1600x900). They are multiplied by `screen height / reference × scale option`, the same factor in both directions: nothing is distorted, and on a wider screen only the anchors move. Colors are `"#RRGGBB"`, `"#RRGGBBAA"` or `[r, g, b, a]`.

| Field | Meaning |
| --- | --- |
| `anchor` | Screen point: `top-left`, `top`, `top-right`, `left`, `center`, `right`, `bottom-left`, `bottom`, `bottom-right`, or `[x, y]` as fractions of the screen. Default `top-left`. |
| `pivot` | Point of the zone placed on the anchor, same values as fractions of the zone. Default: same as `anchor`. |
| `offset` | `[x, y]` moved from that position. |
| `size` | `[width, height]`; 0 fits the content. With a width, text wraps. |
| `reference` | Screen height the zone's pixel values are designed for (240 to 4320). Default 1080. |
| `order` | Drawing order, lower first. Zones holding only `world` items are drawn before all others, under the panels. |
| `visible` | `false` hides the zone without removing it. |
| `background`, `border`, `border_width`, `rounding` | Plain background and border. |
| `frame` | Nine-slice image: `{image, slice = n or [left, top, right, bottom] (image pixels), scale, tint}`. |
| `padding`, `spacing` | Inner margin (`n` or `[x, y]`) and space between items. |
| `text` | Default text style of the zone: `font` (TTF path), `size`, `color`, `shadow`, `shadow_color`, `shadow_offset` (`[x, y]`, default `[1.5, 1.5]`), `outline`, `outline_color`. |
| `items` | List, drawn top to bottom. |

Items (a plain string is a text item):

| `type` | Fields |
| --- | --- |
| `text` | `text`, the text style fields, `align` (`left`, `center`, `right`). |
| `image` | `image` (path), `size` (`n`, `[w, h]`, one side 0 keeps the ratio; default: image size), `tint`, `uv` `[u0, v0, u1, v1]` for an icon in an atlas, `rounding`, `align`. |
| `row` | `items` side by side, centered vertically, `spacing`, text style fields inherited by its items. A row holding a `grow` spans the zone width. |
| `grow` | In a row: takes the width left, to push the next items to the right. |
| `flow` | `items` (text, chip, icon, image, toggle) laid out like a sentence: texts are cut into words and every line wraps at the zone width. `spacing` between non-text items (default 5), `line_gap` between lines. Punctuation sticks to what precedes it. Chinese and Japanese text, which has no spaces, may wrap between any two characters, never before closing punctuation, small kana or `ー`, nor after an opening bracket. |
| `chip` | `text` on a rounded background, such as a key: text style fields (default dark text, no shadow), `background` (default `#F2EFE7`), `rounding` (3), `padding` (horizontal, 4), `box` `[min width, height]` (`[17, 17]`). |
| `icon` | `path`: SVG path data stroked as lines (`M L H V A Z`, absolute or relative; curves are refused), `viewbox` (square side, 24), `size` (18), `stroke` (1.8, in viewbox units), `color` (default: the text color). |
| `toggle` | `on`, `size` (`[26, 14]`), `color` (track off), `on_color` (track on, `#C9A24E`), `knob`. |
| `spacer` | `size`: height. |
| `separator` | `color`, `thickness`: a line across the zone. |
| `progress` | `value` 0 to 1, `size`, `color`, `background`, `rounding`. |
| `grid` | `rows`: strings of ASCII characters (64 rows and 64 characters at most), one cell per character; `colors`: character → color, a character without a color leaves its cell empty; `marks` (optional): character → color of a centred square of about half the cell, drawn over its color, to flag a cell without hiding what it holds; `cell` (side, 8), `gap` (between cells, 1), `rounding`. For maps, shapes or small charts drawn cell by cell in a single item. |
| `row` frame | A row may have a frame: `background`, `border`, `rounding`, `padding` = `{x, y}` around its content. In a `flow`, a row is one piece, never cut across two lines (a key chip with its description). |
| `flow` frame and indent | A flow may have the same frame, drawn over the zone width, its lines wrapping inside the `padding`. `indent` starts every line after the first that much further right: with a caption of fixed width first (a `chip` with a `box`), the items of each line line up under each other. |
| `drum` | A choice of several values as a turning cylinder: `options` (1 to 8 texts), `index` (1-based, the one in the middle), `box` (width and height, 96 × 26), text style (`font`, `size`, `color`), `dim` (color of the options above and below), `background`, `border`. With an `id`, a new `index` turns the drum there, the short way round, in about a quarter of a second. |
| `world` | Points and segments of the game world, drawn where the game's camera puts them on the screen, at every frame, over the whole screen whatever the zone's place. `points`: up to 256 `{at = {x, y, z}, color, size, shape}` (meters; `size` in reference pixels, 12; `shape` `ring`, `cross` or `dot`); `cells`: `{origin = {x, y, z}, cell, box = {x, y, z}, data, colors}`, a box of cells in the world (the corner of its first cell and the cell side in meters; `data` and `colors` as for `voxels`, built on the overlay's thread in the same way), its faces turned to the camera filled and lit by their direction, the farthest first, at most 30000, then their edges drawn over all of them (no fill covers an edge); `smooth`: only the edges where the surface turns, not those between two cells of a flat side; `edge_opacity` (0 to 1, 0.9): the edges' opacity, in their cell's color. `solids`: `{origin, cell, box, data}`, filled cells of the world (`#` in `data`, run-length as for `voxels`, 256 per side at most): the item's cells (the first 4000 faces), quads and lines behind them, seen from the camera (a walk, cell by cell, from their middle to the eye), are drawn lighter. In `cells`, `hide_hidden = true`: the faces of the cells hidden that way are not drawn at all (every face tested, not only the first 4000: the results are kept per mesh and tested again, at most 2 ms per frame for all items, after the eye moved 2 cm, a face keeping its last result meanwhile); `hidden_dashed = true`: they are drawn by their edges only, dashed, in their color; `hide_own = true`: the item's own cells (those with a color) hide each other too. A face tested at its middle and its four corners (a little inside) that do not agree is cut in 4 x 4 pieces tested at their middles: only its pieces hidden are left out (or dashed), each row's pieces alike drawn as one, its edges drawn only along the face's border. `only_in_solids = true`: the cells are drawn only inside the box of `solids`, and none while the eye is outside it (elsewhere what hides them is not known; for a mod giving the box holding the cells and the eye). `features` lists `hide_hidden` and `only_in_solids`. `quads`: up to 64 `{corners = {four {x, y, z}}, color}`, filled flat quadrilaterals (meters, corners in order), drawn under the lines. `lines`: up to 2048 `{from, to, color, width, dashes}` (`dashes`: the line cut into that many dashes of equal length, gaps as long between them, the first at `from` and the last ending at `to`; 1 by default); `boxes`: up to 1024 `{from, to, color, width, dashes}`, the 12 edges of the box between the opposite corners `from` and `to` (meters), each drawn as a line of `dashes` (at most 16384 segments in all once cut); `aim_face`: `{color, width, origin = {x, y, z}, cell}`, the face the building cursor aims at, outlined at every frame from the cursor read for that frame (grid of `cell` meters, 0.5, from `origin`), not drawn while it aims at nothing; `camera_lead`: seconds (-0.2 to 0.2) the camera is foreseen ahead from its mean turn and move over the last 0.1 s (at most 8 degrees); negative, the camera read that long before is used instead. How the camera read changes is then logged every 5 s. The camera is the local client's, read from ShroudForge's runtime (`KfcRuntimeReadLocalCamera`) for each frame: nothing is drawn without it. |
| `voxels` | A box of cells seen in 3D, in a view of `size` reference pixels (240 × 180). `box`: `{x, y, z}` cells, 1 to 256 each; `cells`: run-length text of the cells, x fastest, then y, then z, one ASCII character per cell, a decimal count before a character repeats it (`"40.3#"` is 40 `.` then 3 `#`); `colors`: character → color, a character without a color is empty; `marks` (optional): character → color of a dot drawn on top of its cells. Camera: `yaw` (degrees, 0 looks along +z with +x on the right and +y up), `pitch` (degrees looking down, 30), `zoom` (1 fits the box), `spin` (degrees per second added to the yaw by the overlay, so a turning view needs no new zone). `opacity` (0 to 1): the view over the game; see-through (this or the layer's opacity below 1), the solid view is drawn opaque into an off-screen image as large as the screen, then laid over the game at once, so it is the opaque view made lighter (where the renderer cannot create that image, only the faces seen from the camera are drawn, a ray from five points of each face). `xray`: every face turned to the camera, the faces between cells of different characters too, those of the `ghost` characters at `ghost_alpha` (0.6); `edge`: outline color of the faces (cells of 3 pixels or more); `plain`: in solid view, no outlines nor anti-aliased borders, one continuous surface even see-through; `ease`: seconds a new `yaw` or `pitch` takes to be reached (the view turns instead of jumping, kept per zone), 0 at once; `follow_camera`: the view turns with the game's camera at every frame, its yaw being the camera's plus `camera_offset` degrees (`yaw` stays the angle used while the camera cannot be read); `perspective` (0 to 1): 0 a parallel view (lines stay parallel), up to 1 a perspective with a field of 90 degrees, the box still fitting the view; `grid` and `grid_color`: lines on the floor of the box every `grid` cells; `lines`: up to 256 `{from, to, color, width, dashes}` in cells of the box (a cell's centre is its index plus 0.5), drawn over everything; `max_faces` (1000 to 400000, 120000): most faces of the mesh drawn, a coarser one beyond. The faces are built once on the overlay's own thread after the zone is set (the zone is set at once; the view shows nothing at first, then the faces it replaces until the new ones are ready), with, for a box over 64 cells on a side, two coarser meshes of 2 and 4 cells a cell (each cell taking the drawn character the rarest in the box among those it covers). A zone set again with the same `box`, `cells`, `colors` and `marks` (its yaw, lines or labels changed) keeps the faces already built, at whatever place they are among its views; so do the `cells` of `world` items, and their `solids` are decoded once for all the items that share them. They are drawn from the finest mesh whose cells take 2 pixels or more and whose faces fit `max_faces`, from the farthest (an order kept while the camera does not move), lit by their direction. |

## Test

Build with `dev/build/build_game_overlay.ps1`. Copy `build/game-overlay/Release/overlay_present_test.exe` beside the built layer as `enshrouded.exe`. Then run it with `VK_ADD_IMPLICIT_LAYER_PATH` set to that folder and `SHROUDFORGE_OVERLAY_ENABLE=1`:

```powershell
enshrouded.exe modules/game-overlay/tests/assets capture.bmp
```

It publishes three test zones, presents frames and saves the last presented image.
